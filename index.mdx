Neuron is a runtime for building and operating complex software systems from composable, executable capabilities.

Software should be composed from things that can do something, connected by explicit relationships, and operated by a runtime that does not need to understand what those things are.

## Core primitives

| Primitive | Description |
| --- | --- |
| **Assembly** | Defines what exists and how it is connected. |
| **Capability** | Exposes one executable capability. |
| **Binding** | Defines how two capabilities communicate. |
| **Capability Runtime** | The machinery that runs a Capability. |
| **Instance** | A living realization of an Assembly. |
| **N.O.R.E.** | The Neuron Operational Runtime Engine that operates registered Assemblies. |

```mermaid
flowchart LR
  A[Assembly] --> B[Capabilities]
  B --> C[Bindings]
  C --> D[Instance]
  D --> E[N.O.R.E. Runtime]
  E --> F[Capability Runtimes]
```

## Why Neuron

| Concern | Traditional approach | Neuron |
| --- | --- | --- |
| **Composition** | Ad-hoc wiring across services and functions | Explicit bindings define relationships at the assembly level |
| **Execution** | Workflow engines tightly couple definition and execution | A hard boundary between defining an assembly and the mechanisms that execute it |
| **Portability** | Hard to move from local to distributed | The same logical composition runs locally and can be distributed without redefining architecture |
| **Capabilities** | Limited to a single process or framework | A capability can be a process, WASM module, built-in function, or another assembly |
| **Isolation** | Mixed security boundaries | Capability runtimes run out-of-process or in isolation with explicit contracts |

## How an Assembly runs

<Steps>
  <Step title="Define">
    Author an Assembly in any language that implements the Neuron assembly protocol. Neuron ships with a TypeScript SDK (`@neuron/sdk`) and a YAML authoring surface, but it is language-agnostic: any language SDK or implementation that emits the canonical assembly format works.
  </Step>
  <Step title="Build">
    `neuron build` compiles sources into a canonical manifest, resolves and installs capability runtimes, and registers the assembly with N.O.R.E.
  </Step>
  <Step title="Start the runtime">
    Run `neuron` in the project directory to start the foreground project runtime (N.O.R.E.).
  </Step>
  <Step title="Run">
    `neuron run` sends a synchronous request to execute the assembly and returns the result.
  </Step>
  <Step title="Operate">
    N.O.R.E. executes capabilities through their capability runtimes based on explicit bindings.
  </Step>
</Steps>

<Note type="info">
Neuron is in active development. The first public release is v0.1.0.
</Note>

## Quick start

```bash
neuron build
neuron run --params '{"order": {...}}'
```
